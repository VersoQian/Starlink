## 18 / 32 · 3.1 Ideation Coach：生成前补全

### 页首结论

> 先补足关键假设，再进入多智能体生成：避免系统在信息不足时“自信地补写”。

### 页面内容

**为什么需要 Coach**

- 用户最初通常只有一句产品想法。
- 目标客户、核心痛点、收入方式、验证路径与关键风险往往尚未明确。
- 如果直接生成九宫格，模型只能隐式猜测，后续结论难以校验。

**Coach 做什么**

`读取当前想法` → `识别缺失假设` → `自适应追问` → `用户补充` → `形成结构化种子`

**九类引导节点**

`核心想法` · `客户痛点` · `价值角度` · `关键假设` · `验证渠道` · `收入流` · `风险` · `证据` · `AI 反思`

### 页面底部结论

> Coach 不负责直接生成画布，而是为 Supervisor 提供更可靠的初始状态。

### 视觉建议

左侧保留“信息不足”的三条原因；右侧保留九类节点；底部只画一条五步闭环。删除实现文件名和过多英文说明。

## 19 / 32 · 3.2 渐进式生成与覆盖检查

### 页首结论

> 将“一次生成”拆成可检查流程；监督器确定性核验九维填充，缺失维度最多回补三轮。

### 页面内容

`① 不完整想法` → `② Coach 补全` → `③ Supervisor 分派` → `④ 三个生成器并行生成 + 检索` → `⑤ 九维覆盖检查` → `⑥ 可编辑画布`

在 `⑤ 九维覆盖检查` 下增加回环：

`缺失维度` → `定向回补，≤ 3 轮` → `再次检查`

**覆盖检查机制**

- 检查“是否完成指派”，避免某个维度无人负责。
- 检查“是否实际填充”，不信任智能体自报完成。
- 只重生成缺失单元，其余内容通过 `merge-by-identity` 保留。

### 页面底部实验提示

**DeepSeek-V3 后端 · Key Partnerships 空缺**

`gpt-solo：12 / 12` → `Starlink：0 / 12`

### 页面底部结论

> 覆盖检查修复的是尾部维度遗漏，而不是笼统声称所有维度质量均提升。

### 视觉建议

延续原页面布局，但将错误的 `19/32 → 19/32` 替换为 `12/12 → 0/12`。数字标签明确写成“KP 空缺案例数”。

## 20 / 32 · 3.3 有限评审循环与 HITL

### 页首结论

> 评审循环用于处理高严重度冲突：局部修复，有限迭代，必要时升级给用户裁决。

### 页面内容

`Critic 发现跨单元冲突`

↓

`Proponent：提出立场与依据`

↓

`Opponent：检索证据并反驳`

↓

`Moderator：结构化裁决`

↓

`resolved：回写画布` / `revise：进入下一轮` / `未解决：升级 HITL`

**约束**

- 仅高严重度冲突进入评审。
- 最多 `≤ 3` 轮，避免无界讨论。
- HITL 提供 `接受`、`修改`、`忽略` 三种选择。
- 裁决、修改与用户决策均写入审计轨迹。

### 页面底部结论

> 该机制的价值是暴露并修复冲突，而不是保证整体均分上涨。

### 视觉建议

保留原来的角色卡片，但减少 JSON 字段展示。可在页脚用小字注明：消融结果中去 debate 后均分无显著差异，因此其定位是局部修复机制。

## 21 / 32 · 3.4 双语混合检索：质量与可靠性分离

### 页首结论

> Dense 保证语义相关，Lexical 保证异常时仍可召回；RRF 将两路结果稳健融合。

### 页面内容

`查询`

↙ `Dense 语义通道：向量相似度`

↘ `Lexical 词法通道：中英关键词匹配`

→ `RRF 融合`

→ `Top-K 证据`

→ `智能体引用`

**检索质量**

- 混合检索 vs 纯向量检索
- 平均相关度 `1.514 → 1.944`
- 提升 `+28.4%`

**降级可靠性**

- 当嵌入服务异常时，Dense 通道退化，Lexical 通道仍可工作。
- hybrid 相对纯向量召回提升 `+8.9% recall@5`。

### 页面底部结论

> `+28.4%` 描述正常场景下的相关度增益；`+8.9% recall@5` 描述降级场景下的召回韧性。

### 视觉建议

保留原流程图。右下角拆成两个并列指标卡，不要把两个实验口径放在同一个大数字中。

## 22 / 32 · 3.5 从检索证据到双向溯源

### 页首结论

> 检索不是终点：每条主张都携带结构化引用，用户可以从画布回到证据原文。

### 页面内容

`① 来源文档`

→ `② 混合检索命中片段`

→ `③ 智能体生成主张 + 引用 token`

→ `④ 画布展示 citation chip`

→ `⑤ 点击回到原文`

**双向溯源**

- 正向：主张 → 支撑证据片段。
- 反向：证据片段 → 引用该证据的画布单元。

**结构化引用类型**

`documentary` 文献证据 · `structural` 结构关联 · `critique` 批评意见 · `insight` 综合洞见

### 页面底部结论

> 引用 token 让 grounding 可展示、可复核，也可计算。

### 视觉建议

保留原有五步链路和“正向 / 反查”示意图。引用类型缩为四个短标签，报告推断标记放到口述或备份页。

## 23 / 32 · 3.6 画布即交互工作区

### 页首结论

> 画布不是一次性结果页，而是用户持续检查、溯源与修订的工作区。

### 页面内容

左侧使用真实系统截图，右侧保留四项能力：

**九宫格结构化视图**

- 九个商业模式维度在同一画布中呈现。
- 也支持自由排布模式。

**摘要卡 + 详情抽屉**

- 卡片用于快速浏览。
- 抽屉承载长文本、引用与编辑。

**单元级编辑与回源**

- 每个单元均可独立修订。
- 点击 citation chip 回到证据片段。

**流式增量合并**

- 新结果按标识合并。
- 修订单元时不必重生成整张画布。

### 页面底部结论

> 这一步直接回应“整块输出不可编辑”的失效。

### 视觉建议

以截图为主要证据对象，避免继续加入过多节点、边和面板数量。数量统计放在备份页。

## 24 / 32 · 3.7 工程保障：可恢复、可降级、可审计

### 页首结论

> 原型之外，系统还需要在外部服务异常和人工暂停后继续运行。

### 页面内容

**可恢复**

- 黑板状态通过 `PostgresSaver` 持久化。
- 网关重启后可按 `thread_id` 从 checkpoint 恢复。
- HITL 暂停可以跨进程继续。

**可降级**

- 嵌入服务异常时，检索回退到 Lexical 通道。
- LLM 连续失败时触发熔断，避免拖垮全局。
- 阶段超时后跳过或快速失败，而不是无限等待。

**可审计**

- `mention`、`subgraph`、`tool` 三层遥测。
- 记录 HITL 决策、智能体交接和工具调用。
- 错误指纹聚合，减少重复告警。

**可演进**

- 已批准记忆按 `session / workspace / user / global` 作用域沉淀。
- 下一次会话由 Supervisor 回灌相关上下文。

### 页面底部结论

> 失败可恢复、依赖可降级、过程可审计、上下文可演进。

### 视觉建议

将原第 24 页和第 26 页合并为四列能力卡。隐私脱敏、RLS、API key 加密作为备份页内容，避免主讲时信息过载。

## 26 / 32 · 3.9 核心机制小结：逐一回应三类失效

### 页首结论

> 核心机制不是功能堆叠，而是针对三类结构性失效逐一设计。

### 页面内容

| 结构性失效 | 对应机制 | 可验证结果 |
| --- | --- | --- |
| 覆盖缺失 | Supervisor 分派 + 九维覆盖检查 + 定向回补 | KP 空缺 `12/12 → 0/12` |

页面右下角补充一条：

### 页面底部结论

### 视觉建议
